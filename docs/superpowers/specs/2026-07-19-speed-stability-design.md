# 字幕视频生成速度与稳定性设计

## 目标

在不降低字幕识别、翻译和视频画质的前提下，减少重复处理、降低多语言软字幕封装成本，并使长任务在停止、异常或服务重启后能够明确恢复。

## 现有能力

当前已实现单工作线程、防重复提交、进程超时与心跳、Whisper 降级、翻译批次断点、源字幕与翻译缓存、VideoToolbox 编码回退和字幕校对后单独重新生成视频。本轮在这些边界上增强，不重新实现已有功能。

## 阶段性能计量

任务记录下列阶段的独立耗时：

- 输入准备与下载。
- 源字幕获取（内置字幕、Whisper 或 OCR）。
- 每个目标语言的翻译。
- 字幕布局与文件输出。
- 软字幕封装或硬字幕编码。
- 整体任务耗时。

计量结果进入 `PipelineResult`，Web 结果和 CLI 都可以显示。时间数据只用于本地诊断，不上传。

## 低风险速度优化

### 多语言软字幕一次封装

当一次任务选择多个目标语言且输出软字幕视频时，FFmpeg 只复制一次视频和音频流，把所有 SRT 作为独立字幕轨写入同一个 MP4。各语言 SRT 仍分别保留。单语言保持现有文件命名与行为。

### 中间结果复用

继续沿用输入视频、音频、源字幕、转写、翻译和画面分析缓存。相同任务仍创建新的时间戳输出目录，避免覆盖用户已经校对过的成品。

## 稳定性

### 原子输出

SRT、ASS、JSON 和视频先写入同目录临时文件，成功后使用原子替换变成正式文件。取消、超时或 FFmpeg 失败不会留下表面可播放但实际损坏的成品。

### 资源与磁盘预检

在输入视频就绪后检查输入文件非空、可写目录和可用空间。软字幕以输入文件大小估算；硬字幕使用更保守的预留系数。空间不足时在转写和翻译之前失败，并显示需要与可用空间。实际视频流可解码性继续由现有 ffprobe/ffmpeg 步骤验证。

### 任务执行边界

当前单工作线程作为重型资源锁保留。新的阶段日志要区分“等待资源”与“正在处理”。进程型工具继续由现有看门狗终止；Python 模型调用按批次保存断点并在批次边界响应取消。

## 保守流水线优化

- 翻译完成的 SRT 可以在后续目标语言翻译时后台封装，但本地重型模型和硬字幕编码不同时抢占资源。
- 软字幕多轨封装等所有目标 SRT 完成后只执行一次。
- OCR 在长视频中使用最大抽帧数保护，并在日志中说明实际采样间隔。默认不使用可能漏掉快速字幕的场景变化过滤。
- 本轮不把 Whisper 切成多个并行子进程。该方案会改变上下文和时间轴，需要单独质量评测。

## 兼容性

- 默认命令行参数保持不变。
- 单语言输出文件名保持不变。
- 现有翻译和转写缓存继续可用。
- 新结果字段为可选，旧任务历史可继续读取。
- macOS 、Linux 和 Windows 在没有 Vision OCR 时仍可启动普通流程。

## 验收

- 完整测试集通过，现有字幕时间轴与翻译结果不变。
- 结果中可查看阶段耗时和总耗时。
- 多语言软字幕任务只运行一次 FFmpeg 封装。
- 任意输出失败时没有不完整的正式文件。
- 磁盘不足在重型阶段之前给出可操作提示。
- 第二次处理同一输入时日志明确显示复用的视频、音频、转写或翻译中间结果。
- 任务取消、子进程超时和模型异常仍保留可继续的字幕与翻译断点。
