# 字幕工具速度、稳定性与易用性升级设计

## 目标

在不改变现有 CLI 和 Web 主流程的前提下，完成三批改进：让长视频处理更可预期，让字幕来源和翻译回退更可靠，让首次使用者能够完成本地配置并安全管理资源。

本轮不包括桌面安装包、用户账号、多租户服务器、绕过 DRM、自动读取浏览器 Cookie 或新的 OCR 引擎实现。

## 第一批：速度与质量

### 性能基准与自动策略

每个任务记录输入准备、字幕来源、逐语言翻译、视频输出和总耗时。根据视频时长、文件大小、目标语言数量、字幕视频模式生成预估处理时间和建议：优先缓存、降低长视频 OCR 抽帧密度、或建议软字幕模式。

估算仅作为提示，不阻止任务。缓存命中、翻译引擎回退和硬字幕重新编码均会更新最终实际耗时。

### 翻译调度

云端翻译保持单账户限流保护。同一引擎的请求串行或低并发执行；不同语言以可恢复的批次推进。z.ai 出现限流、超时或质量异常时，优先使用当前可用本地模型，仍失败再尝试 OpenAI。每次切换会写入日志、任务结果与翻译缓存身份。

本地 NLLB、Whisper、OCR、硬字幕编码继续受重任务资源锁保护，避免争抢内存或 Metal 设备。

### 字幕来源质量评分

`auto` 模式为内置字幕、音频转写和画面 OCR 生成候选质量分。评分依据包括片段数量、有效文字比例、重复比例、过短或过长片段、语言匹配度和 OCR 置信度。优先读取内置字幕；但当候选明显为空、重复或低质量时，允许切换至更高分来源。

手动选择 `embedded`、`audio` 或 `screen-ocr` 时不自动替换来源，只在日志中给出质量警告。

## 第二批：稳定与维护

### 流程边界

将 `pipeline.py` 按职责抽取为输入准备、字幕来源选择、翻译编排、结果输出与任务诊断模块。将 `web.py` 中与 HTTP 无关的表单默认值、错误映射、设置读写移至独立模块。外部 CLI 参数、Web API 响应和既有任务数据库字段保持兼容。

### 下载适配器

下载入口统一返回能力说明和本地视频路径。适配顺序为：YouTube 专用解析、已知公开分享页解析、通用 `yt-dlp` 解析。失败时将结果分类为：不支持、需要登录或 Cookie、受 DRM 保护、临时网络或站点变更。工具不采集 Cookie，也不尝试规避 DRM。

## 第三批：首次使用与资源保护

### 首次使用引导和设置

Web 增加本地设置页，保存非敏感默认项，例如输出目录、Whisper 模型、性能开关和字幕偏好。API Key 保持由环境变量或本地 `.env` 读取；网页只显示“已配置/未配置”，默认不回显或持久化密钥。首次启动时显示依赖、模型和 API 配置缺口，并给出对应操作说明。

### 资源与隐私保护

缓存展示总占用、分类占用和可回收空间。增加可配置缓存上限和过期文件建议清理，但不自动删除用户输出目录。任务启动前继续做磁盘预检查；当缓存超出建议上限时显示警告。

导出和复制诊断日志时，脱敏 API Key、Cookie、授权头、签名 URL 查询参数和用户主目录路径。完整日志仍在本机任务数据库中保留，便于本地排障。

## 验收标准

1. 短视频、长视频、单语言和多语言任务均显示实际阶段耗时与合理预估。
2. z.ai 限流、超时和低质量返回时，日志能说明回退引擎和原因；已完成批次不重复翻译。
3. `auto` 字幕来源在空转写、重复转写和无声硬字幕视频上选取更合理候选；手动来源不被替换。
4. 下载失败能区分常见原因，并保留原始工具错误用于诊断。
5. 首次运行用户能在页面看到缺失依赖、模型和 API 配置状态；密钥不会在 UI 或导出日志中泄露。
6. 所有既有测试通过，并补充新模块的单元测试、回退测试和 Web API 测试。

## 发布策略

每一批完成后运行全量测试、编译检查、前端语法检查和真实视频抽样。全部完成后更新中文主文档、英文补充文档和更新记录；仅在用户明确要求时创建提交并推送 GitHub。
